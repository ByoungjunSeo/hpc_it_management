- 배경: server.js가 `process.env.SESSION_SECRET || '<기본 문자열>'` fallback을 가져

- 요구(택1 또는 병행):
  1. compose `SESSION_SECRET: ${SESSION_SECRET:?...}` 강제 (환경변수 누락 시 기동 차단)
  2. 부트스트랩/서버 기동 시 검사: 미설정·`CHANGE_ME` 접두·32자 미만이면 명확한

- **⚠ 업그레이드 안내 필요 항목**: compose 파일 변경이 포함되는 마이너 릴리스이므로,
  기존 배포처에 새 compose 교체 + .env 확인 절차를 릴리스 노트로 안내할 것.
- **구현 (2026-07-12, 임시 포트 13001 검증 완료)**: 요구 1+2 병행 — server.js 기동 검사

## BL-1 — 선반 1/3U 홀 단위 점유 지원 (✅ 구현 완료 · 운영 반영 대기)

- 배경: 데이터 모델은 이미 hole 단위(1U 내 상/중/하 3홀)로 점유를 표현한다

- **실사용 페인포인트 재확인 (2026-07-11, B-6 종결 시점)**: 선반 포함 입력이 현재

## BL-8 — 이관 audit_logs 표시 시각 UTC 혼재 보정 (✅ 보정 완료 2026-07-12)

- 배경: v1은 audit_logs.created_at을 SQLite `CURRENT_TIMESTAMP`(**UTC**)로 저장해 왔고,
  B-2/B-7 이관은 v1 문자열을 KST(+09:00)로 태깅해 옮김 — 표시 문자열은 v1 화면과 동일하게
  보존됐지만 절대 시각 의미로는 9시간 이른 값. 컷오버 후 신규(v2 네이티브) 기록은 KST 정상.
- 현상: /audit-log에서 **이관분(id≤1476)은 UTC 표기, 신규(id≥1477)는 KST 표기**로 혼재.
  예: 2026-07-11 21:57 KST 로그인(이관분)이 12:57로, 22:14 신규 로그인은 22:14로 표시.
- v1 대비 회귀 아님(v1도 UTC로 표시해 왔음). 데이터 손실 없음 — 보정 시 +9h 일괄 변환 가능.
- 요구(택1, v2.1 정렬 시 결정):
  1. 저장값 일괄 변환: `UPDATE audit_logs SET created_at = created_at + interval '9 hours'
     WHERE id <= 1476` (이관분 특정 가능 — 컷오버 시점 max id 고정)
  2. 표시 계층 보정: id 경계 기준 조건부 렌더(비권장 — 경계 지식이 뷰에 스밈)
- 우선순위: v2.1 백로그 정렬 시 결정. 감사로그 시각 정확성이 요구되는 시점(감사 대응 등)
  전에는 처리 권장.
- **보정 완료 (2026-07-12, 요구 1안 채택 — 게이트 승인 후 실행)**: 조사로 균일 −9h·경계
  id≤1476(1429행) 확정(v1 DDL CURRENT_TIMESTAMP=UTC 단일 경로 × 이관 +09:00 균일 태깅,
  앵커: id 1476 = 21:57 KST 문서화 사건). 2중 백업(pg_dump custom →
  v2/backups/bl8_audit_logs_pre_20260712.dump + DB 내 `audit_logs_bl8_backup` 1429행) 후
  트랜잭션 `UPDATE ... SET created_at = created_at + interval '9 hours' WHERE id <= 1476`
  — 1429행·표본 3건 일치 확인 후 COMMIT. 경계 단조성 회복(1476: 21:57:33 < 1477: 22:14:33),
  역전 0. 코드 무수정(기록·표시 계층 정상). 상세: /tmp/BL8_fix_20260712.md.
- **백업 테이블 처리**: `audit_logs_bl8_backup`은 **2026-07-19 이후 삭제 예정**(사용자 결정
  대기) — 롤백 필요 시 `UPDATE audit_logs a SET created_at=b.created_at FROM
  audit_logs_bl8_backup b WHERE a.id=b.id`.
