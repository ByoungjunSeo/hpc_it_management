# v2.1 백로그

마이그레이션(B-5~B-7) 이후 신기능·개편 트랙. 각 항목은 배경·요구사항 요약 수준이며,
착수 시 별도 설계로 확정한다.

---

## BL-1 — 선반 1/3U 홀 단위 점유 지원 (UI 확장)

- 배경: 데이터 모델은 이미 hole 단위(1U 내 상/중/하 3홀)로 점유를 표현한다
  (rack_unit_start = (U-1)*3 + hole). 랙 렌더/파싱도 홀을 이해함.
- 요구: 배치 입력 UI가 현재 U 단위 위주 → 선반이 1U 내 상/중/하 홀 단위로 점유
  가능하도록 입력 폼 확장(예: "U5 상단만", "U5 중단+하단"). 데이터 변경 없이 UI만.
- **우선순위 근거**: 단순 편의가 아니라 **정확성 문제** — 1/3U 선반을 1U로 입력하면
  틀린 배치 데이터가 기록됨(실물과 랙 배치도 불일치). 데이터 무결성 관점에서 우선.
- **실사용 페인포인트 재확인 (2026-07-11, B-6 종결 시점)**: 선반 포함 입력이 현재
  1U 미만(1/3U 홀 단위)으로 불가 — 실물 배치를 그대로 못 넣는 실사용 마찰로 재확인됨.
  **v2.1 최상위 우선순위 후보**로 정렬(BL 재우선순위화 시 선순위 검토).

## BL-2 — 블레이드 다노드 일괄 사용등록

- 배경: 입고는 섀시+N노드를 한 번에 생성(B-4d-6c #3)하나, 사용등록은 노드별 개별.
- 요구: 섀시 선택 → 노드 수만큼 IP/접속정보/자원 입력 폼을 동적 생성해 한 화면에서
  일괄 사용등록. 노드 공통값(위치/랙) 상속 + 노드별 개별값(IP/자격) 입력.
- **설계 사양 — 관리번호 선택에 따른 조건부 폼**:
  - 섀시 선택 시: **위치 섹션만 표시**(접속/네트워크/하드웨어 섹션 숨김) — 섀시는 물리 배치만.
  - 노드 선택 시: **위치 숨김(섀시에서 상속)** + 나머지(접속/네트워크/하드웨어) 표시.

## BL-3 — 시설 모델 재설계

- 배경: 위치(서버실/장비실/사무실) 모델이 이름 직접 입력 기반이라 중복 이름·정합성
  리스크가 있고, 공간 유형과 랙 보유 여부가 묶여 있다.
  **근거(실증)**: v1 운영에서 중복 room 사고 발생 — "독립개발실3"이 이름 직접 입력으로
  중복 생성됨. 마스터 선택 방식이었으면 방지됐을 데이터 정합성 사고.
- 요구:
  - 위치 선택에서 직접 입력 제거(중복 이름 정합성 리스크 해소) — 마스터에서 선택.
  - 사무실 공간 동적 추가.
  - 공간 유형과 랙 보유 여부 분리: **랙 없는 서버실 공간**·**랙 있는 사무실** 모두 허용.
- **INV-2 반영 (B-6c 조사)**: 입고 직후 `status='active'` + 랙 미배치(rack_id NULL)
  자산의 가시성 갭 — 현재 "보관 장비" 뷰의 "미배치" 정의가 `status IN
  ('inactive','decommissioned')`뿐이라 입고 직후 active 자산이 어느 시설 뷰에도 안 보임
  (v1 동일 동작·회귀 아님, BUG_TRACKING 참조). 재설계 시 **"미배치" 정의 재검토**를
  범위에 포함 — active 미배치 자산의 배치 대기 상태를 시설 뷰에서 노출할지 결정.

## BL-5 — IP 서브넷 관리 (✅ B-6e로 구현 완료)

- **구현 완료 (B-6e, 커밋 c134df6/89ceb0a/7aea9ec)**: subnets 테이블 신설 + 화면 CRUD
  (등록 시 풀 자동생성, 삭제 정책[assigned 차단·reserved 고지]) + syncAssetIps 무수정 활용
  + 풀밖 IP 경고 + 빈 상태 안내 + 동적 zone 섹션 + CIDR /16~/30 + 상세 블록 페이지네이션.
  DEPLOY.md/스키마/마이그레이션 반영. 아래는 원 설계 기록(참고).
- 배경: IP 관리 화면은 `ip_addresses` 풀(서브넷 시딩분)만 조회하는 할당 현황판.
  현재 서브넷은 `SUBNETS_JSON` env로만 주입되고 화면 CRUD가 없음.
- **INV-1 반영 (B-6c 조사)** — 설계 입력:
  - 현상: 사용등록/자산등록 IP는 `asset_ips`에 저장되고 `IpAddress.syncAssetIps`가
    풀을 갱신하나, `syncAssetIps`는 **`UPDATE ... WHERE ip_address=` (풀에 있는 IP만
    assigned)** — 풀에 없으면 무효(INSERT 안 함). v1도 동일(2,304행 시딩 전제).
    클린 설치(SUBNETS_JSON 미설정 → 풀 0)에선 자산 IP가 IP 관리 화면에 안 뜸
    (v1 동일 동작·회귀 아님, BUG_TRACKING 참조).
  - 설계 방향:
    1. **서브넷 CRUD** 화면(추가/수정/삭제) — SUBNETS_JSON env 의존 제거 또는 병행.
    2. 서브넷 등록 시 **풀 자동 생성**(해당 대역의 ip_addresses 행 시딩) — 기존
       `initializeSubnets` 로직 재사용.
    3. **기존 `syncAssetIps`는 무수정 활용** — 풀이 채워지면 현행 UPDATE가 그대로 동작.
    4. **풀 밖 IP는 경고 방침**: 자산에 등록된 IP가 어느 서브넷 풀에도 없으면 화면에
       경고 표시(누락 서브넷 등록 유도) — 조용히 사라지지 않게.
    5. **빈 상태 안내**: 서브넷 0개일 때 IP 관리 화면에 "서브넷을 먼저 등록하세요" 안내.
  - **B-6e로 승격 확정**: 배포(B-6) 과정에서 클린 설치 지원 필수 항목으로 드러나
    v2.1 백로그가 아닌 B-6e 단계로 올림.

## BL-7 — 대량 블록 네비 개선 (/16의 256블록 UI)

- 배경: B-6e 상세 화면은 /24 블록 단위 페이지네이션. /16(256블록)은 블록 링크가
  256개 나열되어 네비가 길다.
- 요구: 큰 대역의 블록 네비를 개선 — 3옥텟 범위 접기/검색·점프 입력(예: "60"→10.x.60),
  또는 사용된(assigned/reserved) 블록 우선 노출 + 나머지 접기. 기능은 정상(스크롤만 김).

## BL-6 — 네트워크 zone 사용자 정의화

- 배경: network_zone이 DB CHECK(`office`/`hpc`/`aidc`) + `appConfig.networkZones`로
  고정되어 TTA 조직 구조에 종속. B-6e 서브넷 CRUD는 이 3종 안에서만 등록 가능.
- 요구: zone을 마스터 테이블/설정으로 사용자 정의화(추가/이름변경) — CHECK 제약 완화
  또는 zone 참조 테이블. 타 팀이 자체 네트워크 구분(예: 사내망/DMZ/관리망)으로 쓸 수 있게.
  B-6e에서 zone은 3종 유지했으므로 후속 개편 대상.
