# IT 자산관리 시스템 v2.0.2 배포 공지

> ⚠ **이 공지는 미발송입니다 — v2.1.0으로 대체됨** (2.0.x는 사내 검증본, 타 팀 배포는 v2.1.0이 첫 정식본).

수신: 배포 대상 팀 인프라 담당자 (Docker 운용 가능 전제)

## 1. 개요

HPC/AIDC 장비실의 서버·모듈·IP·입출고를 웹에서 통합 관리하는 자산관리 시스템입니다.
이번 전달 버전은 **2.0.2**이며, 전달물은 아래 1파일입니다.

- `it-assets-dist-2.0.2.tar.gz`
- sha256: `da9511dabd0c831cd802957c786201188f0c4200a8413ea1b04b665d4e8743a7`
  — 수령 후 `sha256sum`으로 반드시 대조하세요.

tar 안에 앱/DB docker 이미지 2종(오프라인 설치용), 설치 문서(DEPLOY.md),
compose 파일, 환경변수 템플릿(.env.example), 스키마 SQL(+마이그레이션),
백업/복원 스크립트가 모두 들어 있어 **인터넷 없이 설치 가능**합니다.

## 2. 2.0.1 대비 변경 사항

| 구분 | 내용 |
|------|------|
| 검색 | 통합 검색이 **관리번호/자산번호**로도 자산을 찾습니다(결과에 관리번호 표기) |
| 랙 배치 | 선반을 **1/3U(홀) 단위**로 정밀 등록 가능 — "선반 포함" 입력이 U+홀 병행 |
| 데이터 품질 | 실(서버실/사무실) 이름 **중복 방지** — 공백/대소문자 변형까지 차단(앱 검사 + DB 유니크 인덱스) |
| 보안 | **SESSION_SECRET 기동 시 강제 검사** — 미설정/기본값 방치 불가(아래 §4) |
| 문서 | compose 주석·cron 예시 정오표(2.0.1 공지 §5) 원본 반영, 업그레이드 절차(§6) 확충 |

## 3. 설치 (신규)

동봉된 **DEPLOY.md §1(리눅스) / §2(윈도우)** 절차를 그대로 따르면 됩니다.
이미지 적재(docker load) → `.env` 작성 → `docker compose up -d` → 브라우저 접속,
실측 수 분 내 완료(`http://<서버IP>:3001`, 최초 로그인 admin / INITIAL_ADMIN_PASSWORD).

## 4. ★ 보안 필수 조치

`.env.example`을 `.env`로 복사한 뒤 **CHANGE_ME 값 5종을 모두 실제 값으로 변경**하세요.

| 키 | 구분 | 미변경 시 |
|----|------|-----------|
| POSTGRES_PASSWORD | **기동 필수** | compose가 기동 차단(에러) |
| INITIAL_ADMIN_PASSWORD | **최초 기동 필수** | 앱이 안내와 함께 기동 중단 |
| SESSION_SECRET | **기동 필수 (2.0.2 신규 강제)** | **미설정/CHANGE_ME/32자 미만이면 기동이 차단**되고 한국어 안내가 출력됩니다. 32자 이상 무작위 문자열로 설정(생성 예: `openssl rand -hex 32`) |
| SSH_DEFAULT_PASSWORD | 기능 사용 시(SSH 스캔 fallback) | 미설정이어도 기동·일반 사용 무영향 |
| LENDING_ORG_LABEL | 표기용(대여 라벨 기관명) | 기본값 "TTA"로 표기 — 자기 기관명으로 변경 |

> 2.0.1 공지의 "SESSION_SECRET은 시스템이 막아주지 않음" 경고는 **2.0.2에서 해소**됐습니다
> — 이제 시스템이 기동 시점에 검사해 차단합니다.

최초 로그인 후 관리자 비밀번호를 즉시 변경하기를 권장합니다.

## 5. 업그레이드 안내 (2.0.1 → 2.0.2)

이미 2.0.1을 운영 중이면 신규 설치가 아니라 **DEPLOY.md §6 업그레이드 절차**를 따르세요. 요지:

```bash
# 0) sha256 대조 후 전개
# 1) 업그레이드 전 백업 (필수)
bash scripts/backup.sh
# 2) 새 앱 이미지 적재
docker load -i it-assets-2.0.2.tar
# 3) 마이그레이션 적용 (이번 릴리스 1건, 멱등 — 재실행 무해)
docker compose -f docker-compose.prod.yml exec -T db \
  psql -U itadmin -d it_assets < db/migrations/2026-07-12_bl3_room_name_norm_unique.sql
# 4) .env에 APP_IMAGE=it-assets:2.0.2 지정 + 새 compose 파일로 교체 후 재기동
docker compose -f docker-compose.prod.yml up -d
```

- **⚠ 재기동 전 `.env`의 SESSION_SECRET이 32자 이상 실값인지 확인**하세요 — 2.0.2는
  기본값/짧은 값이면 기동이 차단됩니다(§4).
- 이번 마이그레이션(실 이름 정규화 유니크 인덱스)은 적용 전 동명 변형 실이 이미 있으면
  실패합니다 — SQL 파일 상단의 사전 점검 조회로 확인 후 적용하세요.
- DB 데이터·업로드 사진은 named volume에 보존됩니다(`down -v` 절대 금지 — DEPLOY.md §7).

## 6. Known limitation
