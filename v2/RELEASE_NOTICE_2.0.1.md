# IT 자산관리 시스템 v2.0.1 배포 공지

> ⚠ **이 공지는 미발송입니다 — v2.1.0으로 대체됨** (2.0.x는 사내 검증본, 타 팀 배포는 v2.1.0이 첫 정식본).

수신: 배포 대상 팀 인프라 담당자 (Docker 운용 가능 전제)

## 1. 개요

HPC/AIDC 장비실의 서버·모듈·IP·입출고를 웹에서 통합 관리하는 자산관리 시스템입니다.
이번 전달 버전은 **2.0.1**이며, 전달물은 아래 1파일입니다.

- `it-assets-dist-2.0.1.tar.gz` (약 193MB)
- sha256: `f06bf0e543337200f6b859bdfb5dcf5046ba6d74046a6de8c0fe54e7b3383c70`
  — 수령 후 `sha256sum`으로 반드시 대조하세요.

tar 안에 앱/DB docker 이미지 2종(오프라인 설치용), 설치 문서(DEPLOY.md),
compose 파일, 환경변수 템플릿(.env.example), 스키마 SQL, 백업/복원 스크립트가
모두 들어 있어 **인터넷 없이 설치 가능**합니다.

## 2. 요구사항

- Linux 서버 + Docker Engine + Compose v2(`docker compose` 명령) — 이 조합으로 설치 실검증 완료
- Windows도 가능: Docker Desktop(WSL2 백엔드) 클린 설치 검증 완료 (상세는 DEPLOY.md §2)

## 3. 설치

동봉된 **DEPLOY.md §1(리눅스) / §2(윈도우)** 절차를 위에서부터 그대로 따르면 됩니다.
이미지 적재(docker load) → `.env` 작성 → `docker compose up -d` → 브라우저 접속
순서이며, 실측 기준 **수 분 내** 완료됩니다(첫 화면: `http://<서버IP>:3001`,
최초 로그인 admin / `.env`의 INITIAL_ADMIN_PASSWORD).

## 4. ★ 보안 필수 조치 (설치 시 반드시 확인)

`.env.example`을 `.env`로 복사한 뒤 **CHANGE_ME 값 5종을 모두 실제 값으로 변경**하세요.

| 키 | 구분 | 미변경 시 |
|----|------|-----------|
| POSTGRES_PASSWORD | **기동 필수** | compose가 기동을 차단(에러) |
| INITIAL_ADMIN_PASSWORD | **최초 기동 필수** | 앱이 안내 메시지와 함께 기동 중단 |
| SESSION_SECRET | **보안 필수 (⚠ 시스템이 막아주지 않음)** | 아래 경고 참조 |
| SSH_DEFAULT_PASSWORD | 기능 사용 시(SSH 스캔 fallback) | 미설정이어도 기동·일반 사용 무영향 |
| LENDING_ORG_LABEL | 표기용(대여 라벨 기관명) | 기본값 "TTA"로 표기됨 — 자기 기관명으로 변경 |

> ⚠ **SESSION_SECRET 경고**: 이 값을 CHANGE_ME 그대로 두거나 비워도 **시스템이
> 기동을 막아주지 않습니다.** 그 경우 세션 서명 키가 예측 가능한 값이 되어
> 로그인 세션 위조 위험이 생깁니다. 설치 후 `.env`에서 **32자 이상 무작위
> 문자열로 변경했는지 반드시 수동 확인**하세요. (차기 버전에서 기동 시 강제
> 검사로 개선 예정)

최초 로그인(admin) 후에는 화면에서 **관리자 비밀번호를 즉시 변경**하기를 권장합니다.

## 5. 문서 정오표 (패키지 재생성 없이 본 공지로 보완하는 2건)

1. `docker-compose.prod.yml` **상단 주석**의 `*.tar.gz` + `gunzip -c … | docker load`
   안내는 구버전 잔재입니다. 실제 동봉 이미지 파일은 무압축 `.tar`이며,
   **DEPLOY.md의 `docker load -i <파일>.tar` 절차가 정본**입니다.
2. DEPLOY.md §5의 cron 예시 경로 `/path/to/v2`는 **실제 전개 디렉토리
   (`it-assets-dist-2.0.1`)의 경로**로 바꿔 읽으세요.

## 6. 업그레이드 예고

향후 패치/기능 릴리스는 이번과 동일하게 **새 dist tar 재배포** 방식입니다.
업그레이드 시에는 반드시 동봉 `scripts/backup.sh`로 **DB 백업을 먼저** 수행한 뒤
새 이미지를 적재·재기동하며, DB 스키마 변경이 포함된 버전은 마이그레이션 SQL과
적용 순서를 릴리스 노트로 함께 전달합니다. (상세 절차는 DEPLOY.md의
"업그레이드" 절 참조)

## 7. Known limitation

- 랙 실장도에서 **1U 미만(1/3U) 선반 장비의 정밀 표기**는 현재 미지원 —
  v2.1에서 개선 예정입니다. 해당 폼팩터 장비는 당분간 1U 단위로 등록하세요.
