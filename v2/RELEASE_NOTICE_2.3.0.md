# IT 자산관리 시스템 v2.3.0 배포 공지

수신: 배포 대상 팀 인프라 담당자 (Docker 운용 가능 전제)

## 1. 개요

HPC/AIDC 장비실의 서버·모듈·IP·입출고를 웹에서 통합 관리하는 자산관리 시스템입니다.
이번 **2.3.0**은 v2.2.2 대비 **기능 추가 + 버그 수정 릴리스**입니다. **DB 스키마 변경은 없습니다.**
수냉(DLC) 랙에 들어가는 **랙 내장형 CDU**를 랙/U 단위로 배치·관리할 수 있게 되었고, 사용등록 미리보기·
자산 수정 폼의 CDU 관련 결함(1c~1i)을 바로잡았습니다. PoC 체험용 **데모 데이터 스크립트**도 포함됩니다.
전달물은 아래 1파일입니다.

- `it-assets-dist-2.3.0.tar.gz` (전달 번들)
- 앱 이미지 tar `it-assets-2.3.0.tar` (번들 내부, `docker load` 대상)
  - sha256: `06653ac52f33a013d705f3178e31e1dcd17d5d0a70ef61a998063cf8e74fd872`
  - 적재 전 `sha256sum it-assets-2.3.0.tar` 로 **반드시 대조**하세요(이미지 `it-assets:2.3.0`).

tar 안에 앱/DB docker 이미지 2종(오프라인 설치용), 설치 문서(DEPLOY.md), compose 파일,
환경변수 템플릿(.env.example), 스키마 SQL, 백업/복원 스크립트가 모두 들어 있어
**인터넷 없이 설치 가능**합니다.

## 2. v2.2.2 → v2.3.0 주요 변경

### 2-1. 새 기능 (사용자 관점)

| 기능 | 설명 |
|------|------|
| 랙 내장형 CDU | **CDU를 랙/U에 직접 배치**할 수 있습니다. 사용등록·자산 등록/수정 화면의 **"설치 형태" 선택**으로 _랙 내장형(랙+U)_ 과 _독립형(서버실+연결 액침탱크)_ 을 전환합니다(상호배타). 랙 배치도에도 다른 장비처럼 표시됩니다. |
| 랙 유형 DLC | 랙 생성/수정 시 **랙 유형에 DLC(수냉)** 를 선택할 수 있습니다(기존 서버랙·액침탱크에 추가). |
| 랙 상세 — 연결 설비 표시 | 랙 상세 화면에 해당 랙에 **연결된 설비(연결 액침탱크 등)** 를 함께 보여줍니다. |
| 사용등록 미리보기 — 현재 위치 강조 | 사용등록 랙 미리보기에서 **대상 장비의 현재 위치를 강조**해(자기 자신은 충돌 대상에서 제외) 배치 확인이 쉬워졌습니다. |
| 데모 데이터 스크립트 | PoC 체험용 **DEMO- 가상 데이터**(서버실·랙·장비·부품·IP·대여)를 한 번에 넣는 스크립트를 앱 이미지에 포함했습니다(§3·DEPLOY.md §9). **빈 신규 설치본에서만** 동작합니다. |

### 2-2. 버그 수정 (사용자 관점)

| 버그 | 사용자 관점 변경 |
|------|------|
| BUG-27 | **사용등록 미리보기에서 Unit을 비워도 기존 랙 위치가 유지**됩니다 — 프리필 시 Unit 미기입분이 서버의 기존 U 배치를 지우던 문제 해소. |
| BUG-28 (prefill 매핑) | **관리번호가 중복일 때 사용등록 프리필이 '사용 중(active)' 자산을 우선 매핑**하고 중복 안내를 표시합니다(이전엔 마지막 행으로 덮어써 엉뚱한 자산이 채워질 수 있었음). *※ 중복 관리번호 자체의 근본 원인(아래 §8)은 별도.* |
| BUG-30 | **자산 유형·관리번호를 바꾸면 이전 자산의 프리필 잔여값이 깨끗이 초기화**됩니다 — 접속정보·IP·하드웨어 동적 행과 소유구분이 남아 엉뚱하게 저장되던(특히 IP 잔여행으로 풀이 재할당되던) 위험 차단. |
| BUG-31 | **랙 내장형 CDU를 수정 후 무변경 저장해도 랙 배치가 유지**됩니다 — 수정 폼에 CDU 랙 입력이 없어 저장 시 랙/U가 사라지던 문제 해소. |
| 독립형 CDU·칠러 블레이드 오인 | **독립형 CDU·칠러(액침탱크 연결) 수정 화면에서 블레이드 노드 안내 배너·위치 잠금이 더는 뜨지 않고**, 무변경 저장 시 서버실·연결 설비가 유지됩니다(실제 블레이드 노드는 기존 동작 유지). |
| BUG-32 | **DLC 랙이 랙 상세에 "DLC 서버랙"으로 표시**됩니다 — 기존엔 유형이 "서버랙"으로만 보여 DLC 구분이 안 되던 표시 문제 해소(목록 배지·제목 포함). |
| BUG-33 | **랙 상세 "서버실:"에 서버실 이름이 표시**됩니다 — 조인 누락으로 공란이던 문제 해소. |
| BUG-34 | **대시보드 차트가 인터넷 없이도 표시**됩니다 — Chart.js를 외부 CDN 대신 앱에 포함(오프라인 사내망 대응). |

> 위 수정은 사용등록·자산 폼의 CDU/프리필 동작을 바로잡는 연속 수리(1c~1i)와 랙 표시·오프라인 보강(BUG-32·33·34)입니다.

## 3. 설치 (신규)

동봉 **DEPLOY.md §1(리눅스)/§2(윈도우)** 절차 그대로. 이미지 적재(docker load) → `.env` 작성 →
`docker compose up -d` → 브라우저 접속(`http://<서버IP>:3001`, 최초 admin / INITIAL_ADMIN_PASSWORD).
DB 스키마는 첫 기동 시 자동 생성됩니다. (v2.2.2와 **스키마 동일** — 아래 §5 참조.)

> ⚠ **재설치/이전 버전 위 재설치 시 볼륨 청결 필수.** DB 스키마는 **빈 데이터 볼륨에서만** 자동 생성됩니다.
> 완전 새 설치는 `docker compose -f docker-compose.prod.yml down -v`(⚠ 데이터 삭제)로 볼륨을 비운 뒤
> `up -d` 하세요.

> **PoC 데모 데이터(선택)**: 빈 설치본에서 체험용 데이터를 넣으려면
> `docker exec it-assets-app-1 node --no-warnings scripts/seed-demo.js` (DEPLOY.md §9).
> 자산·서버실·서브넷·부품이 하나라도 있으면 **아무것도 하지 않고 종료**합니다. ⚠ **운영 서버 실행 금지.**

## 4. ★ 보안 필수 조치 (.env)

`.env.example` → `.env` 복사 후 **CHANGE_ME 값 변경**. v2.2.2와 **동일**(POSTGRES_PASSWORD·
INITIAL_ADMIN_PASSWORD·SESSION_SECRET·CREDENTIAL_ENCRYPTION_KEY·SSH_DEFAULT_PASSWORD·LENDING_ORG_LABEL).
**신규 환경변수 없음.**

> ⚠ **CREDENTIAL_ENCRYPTION_KEY 분실 시 저장된 장비 자격증명을 복구할 수 없습니다.** DB 백업과 **별도 장소**에
> 보관하세요.

## 5. 업그레이드 (2.2.2 → 2.3.0) — **스키마 변경 없음, 이미지 교체 후 재기동만**

v2.3.0은 **DB 스키마 변경·신규 마이그레이션이 없고, npm 신규 의존성도 없습니다.** 이미지 교체 + 재기동만 하면 됩니다.

```bash
# 1) 백업(권장) → 2) 새 이미지 적재
bash scripts/backup.sh
docker load -i it-assets-2.3.0.tar
# 3) .env에 APP_IMAGE=it-assets:2.3.0 로 교체(또는 기본값 사용) 후 재기동
docker compose -f docker-compose.prod.yml up -d
```

- **마이그레이션 실행 불필요** — 2.2.2에서 2.3.0으로 올릴 때 적용할 신규 `.sql`이 **없습니다**
  (db/스키마/migrations 변경 0건, package.json 의존성 변경 0건).
- ⚠ `down -v` 절대 금지(데이터·업로드 named volume 보존). 재기동 전 SESSION_SECRET(32자+)·
  CREDENTIAL_ENCRYPTION_KEY(hex64) 실값 확인.
- 호스트에서 앱을 직접 구동하는 배포(비-compose)라면 `git pull` 후 `sudo systemctl restart it-assets-v2`
  로 충분합니다.

## 6. 기존 데이터 참고 (자동 보정 없음)

v2.3.0의 수정은 **업그레이드 이후 발생하는 동작**을 고칩니다. 아래는 과거 데이터 관련 참고사항입니다.

- **BUG-31 이전에 랙 배치가 사라진 CDU**가 있으면(수정→무변경 저장으로 랙/U 유실), 업그레이드 후
  자산 수정 화면에서 **설치 형태=랙 내장형**으로 다시 지정해 1회 재배치하세요(자동 복원 아님).
- v2.2.2 §6(BUG-24 부품 사진 `entity_id=0`, BUG-25 반납/비활성 IP 점유)의 **수동 점검 항목은 그대로 유효**합니다.
  해당 릴리스 노트의 읽기 전용 점검 쿼리로 설치본별 자가 점검하세요.

## 7. 검증 범위 (중요)

- 위 기능·수정(랙 내장형 CDU, 1c~1i)은 **격리 스택에서 HTTP 실경로 검증까지 완료**했습니다.
- **운영 인수(실 사용자 브라우저 확인)는 미완**입니다. 업그레이드 후 아래를 인수하세요:
  - 랙 생성 시 **DLC 유형** 선택·저장
  - CDU 사용등록을 **랙 내장형**으로 → 랙/U 배치 → 랙 배치도 표시
  - 랙 내장형 CDU **수정 → 무변경 저장 → 랙 배치 유지**(BUG-31)
  - 액침탱크 + **독립형 CDU** 연결 → 수정 화면에 블레이드 배너 없음, 무변경 저장 후 연결 유지
  - 사용등록에서 **관리번호를 다른 값으로 바꾸면** 접속정보·IP 행 초기화(BUG-30)

## 8. Known limitation / 알려진 이슈

- **BUG-26 — 사용등록 경로 U 겹침 미검사**: 사용등록에서 랙 U 구간이 기존 장비와 겹쳐도 막지 않습니다
  (자산 등록/수정 경로는 겹침 검사 있음). 배치 전 랙 배치도로 공간을 확인하세요. *(다음 릴리스 보완 예정)*
- **BUG-28 — 관리번호 UNIQUE 제약 부재(근본 원인)**: 서로 다른 장비에 **같은 관리번호**가 저장될 수 있습니다.
  2.3.0은 프리필 매핑을 'active 우선'으로 완화했을 뿐, DB 유일성 제약은 **미도입**(스키마 변경 동반이라 보류).
  중복 관리번호는 운영상 피해 주세요. *(스키마 변경 릴리스에서 UNIQUE 도입 검토)*
- **BUG-29 — 일부 반납 경로에서 rack_id 미해제**: 과거 반납분 중 랙 배치(`rack_id`)가 해제되지 않고 남아
  랙 배치도·"랙 미지정" 집계에 잔재로 보일 수 있습니다(확인 사례 6건). **조사 예정이며 본 릴리스 미포함.** *(IP 회수 BUG-25와 동류·별건)*
- **SEC — 사용등록 프리필 시 비밀번호 평문 표시**: 관리번호로 기존 자산을 프리필할 때 접속정보의 비밀번호가
  화면/폼 값에 **평문으로 노출**될 수 있습니다. 공용 화면·화면 공유 시 주의하세요. *(별도 보안 수리 대상)*
- (2.2.2 승계) 웹 백업 생성은 compose 배포에서 비동작 — 호스트에서 `bash scripts/backup.sh`(CLI) 사용.
  재고 점검은 MVP 범위(배지·추이 차트·보고서는 추후).
