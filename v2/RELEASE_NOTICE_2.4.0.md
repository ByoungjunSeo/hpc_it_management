# IT 자산관리 시스템 v2.4.0 배포 공지

수신: 배포 대상 팀 인프라 담당자 (Docker 운용 가능 전제)

## 1. 개요

HPC/AIDC 장비실의 서버·모듈·IP·입출고를 웹에서 통합 관리하는 자산관리 시스템입니다.
이번 **2.4.0**은 **칠러 → CDU 1:N 냉각 연결(CDU-2)** 기능 릴리스입니다. 칠러 1대가 여러 CDU에
냉각을 공급하는 실제 배관 구조(칠러 → Y밸브 → 독립형 CDU + 랙 내장 CDU)를 표현할 수 있습니다.
**DB 스키마 변경(컬럼 1개 추가)이 포함**되므로 업그레이드 시 마이그레이션을 적용해야 합니다.

- `it-assets-dist-2.4.0.tar.gz` (전달 번들)
- 앱 이미지 tar `it-assets-2.4.0.tar` (번들 내부, `docker load` 대상)
  - sha256: `9aa47b2a4bf66de6eb48fe0d62ea64a3ad21fcb866f2d2d0816ddd70118aecaf`
  - 적재 전 `sha256sum it-assets-2.4.0.tar` 로 **반드시 대조**하세요(이미지 `it-assets:2.4.0`).

tar 안에 앱/DB docker 이미지 2종(오프라인 설치용), 설치 문서(DEPLOY.md), compose 파일,
환경변수 템플릿(.env.example), 스키마 SQL, **마이그레이션 SQL**, 백업/복원 스크립트가 모두 들어 있어
**인터넷 없이 설치 가능**합니다.

## 2. v2.3.0 → v2.4.0 주요 변경

### 2-1. 새 기능 — 칠러 → CDU 냉각 연결 (CDU-2)

| 기능 | 설명 |
|------|------|
| 공급 칠러 지정 | CDU(사용등록·자산 등록/수정)에 **"공급 칠러"** 선택이 생겼습니다. **독립형·랙 내장형 CDU 모두** 지정 가능하며, 칠러 1대를 여러 CDU에 지정할 수 있습니다(1:N). |
| 칠러 상세 — 공급 중인 CDU | 칠러 상세에 **이 칠러가 공급 중인 CDU 목록**이 표시됩니다. |
| 랙 상세 — CDU→칠러 | 랙 상세 연결 설비에 각 CDU의 **공급 칠러**가 함께 표시됩니다. |
| 탱크 상세 — CDU의 칠러 | 탱크 상세의 연결 CDU 목록에 각 CDU의 **공급 칠러**가 함께 표시됩니다. |
| 칠러 폼 정리 | 칠러는 더 이상 액침탱크에 직접 연결하지 않습니다 — 칠러 폼에서 **"연결 액침탱크"가 제거**되었습니다(기존 칠러의 탱크 연결은 마이그레이션이 CDU의 공급 칠러로 이전). |

### 2-2. 동작 규칙

- **공급 칠러 대상 검증**: 새로 지정/변경 시 대상은 **활성(active) 칠러**만 허용(아니면 거부). 자기 자신 금지.
  이미 지정된 참조는 대상 칠러가 비활성이 돼도 **유지**됩니다.
- **칠러 반납 시**: 공급받던 CDU의 참조는 **유지**되며, CDU 상세·칠러 상세에 **"공급 칠러 반납됨"** 경고가 표시됩니다.
- **칠러 삭제 시**: 공급 중인 CDU가 있으면 **삭제가 막힙니다**(먼저 CDU의 공급 칠러를 변경/해제).
- `parent_asset_id`(독립형 CDU → 탱크)와 공급 칠러는 **직교**(상호 독립)입니다. CDU-1 랙↔탱크 상호배타 규칙은 그대로.

## 3. 설치 (신규)

동봉 **DEPLOY.md §1/§2** 절차 그대로. 신규 설치는 첫 기동 시 스키마(공급 칠러 컬럼 포함)가 자동 생성되어
**마이그레이션이 불필요**합니다. 접속 `http://<서버IP>:3001`(admin / INITIAL_ADMIN_PASSWORD).

## 4. ★ 보안 필수 조치 (.env)

`.env.example` → `.env` 복사 후 **CHANGE_ME 값 변경**. v2.3.0과 **동일**, **신규 환경변수 없음**.

## 5. 업그레이드 (2.3.x → 2.4.0) — **DDL 포함, 마이그레이션 필요**

`assets.cooling_source_asset_id`(칠러 참조, `ON DELETE SET NULL`) 컬럼이 추가됩니다.
**순서: 백업 → 마이그레이션 → 확인 → (운영 데이터 조치) → 재기동 → 브라우저 확인.**

```bash
# (DB 컨테이너명은 배포에 맞게 — 단독 컨테이너면 it-assets-db, compose 표준은 it-assets-db-1)
# 1) 백업(필수)
bash scripts/backup.sh

# 2) 마이그레이션 (멱등 — 여러 번 실행해도 안전. 한 탱크에 칠러 2대 이상이면 자동 중단·롤백)
docker exec -i <DB컨테이너> psql -U itadmin -d it_assets < db/migrations/2026-10-06_1_cdu2_cooling_source.sql

# 3) 적용 전후 확인(읽기 전용)
docker exec -i <DB컨테이너> psql -U itadmin -d it_assets < db/migrations/2026-10-06_1_cdu2_cooling_source.verify.sql

# 4) 새 이미지 적재 + .env 태그 교체 후 재기동
docker load -i it-assets-2.4.0.tar
#   .env: APP_IMAGE=it-assets:2.4.0
docker compose -f docker-compose.prod.yml up -d
```

- 마이그레이션은 **기존 "칠러→탱크" 연결을 "그 탱크의 CDU.공급 칠러 = 칠러"로 자동 이전**하고,
  칠러의 탱크 직결(`parent_asset_id`)을 NULL로 바꿉니다.
- ⚠ `down -v` 절대 금지(데이터 보존). 재기동 전 SESSION_SECRET·CREDENTIAL_ENCRYPTION_KEY 실값 확인.

## 6. ★ 운영 데이터 조치 (설치본별 수동 — 선택)

마이그레이션은 **탱크를 통해 연결돼 있던 CDU**만 자동 귀속합니다. 데이터상 칠러와 연결고리가 없던
**랙 내장 CDU**가 실제로는 같은 칠러의 공급을 받는 경우, 1회 수동 귀속이 필요합니다.

- 본 시스템(컴퓨팅지원팀 운영본): 리허설 결과 **칠러 TPC-CHI-01이 독립형 CDU(TPC-CDU-01)에 자동 귀속**되며,
  **랙 내장 CDU(TPC-CDU-02)는 `db/ops/cdu2_ops_data_*.sql`로 같은 칠러에 수동 귀속**(관리자 승인 후 적용).
- 적용 전 `...verify.sql`로 현황을 확인하고, 조치 후 "칠러 1대가 CDU 2대를 공급"인지 재확인하세요.
- **읽기 전용 확인 쿼리**와 조치 SQL은 트랜잭션으로 감싸져 있어 영향 행수 확인 후 COMMIT/ROLLBACK 가능합니다.

## 7. 검증 범위 (중요)

- CDU-2 기능·마이그레이션은 **격리 스택 + 운영 DB 덤프 리허설까지 완료**했습니다
  (멱등 재적용, 칠러 2대/탱크 가드 중단, 신규 설치 스키마 ↔ 마이그레이션 결과 동등, 참조 무결성).
- **운영 인수(실 사용자 브라우저 확인)는 미완**입니다. 업그레이드 후 아래를 인수하세요:
  - CDU(독립형·랙 내장형) 등록/수정에서 **공급 칠러** 지정·저장
  - 칠러 1대를 **여러 CDU**에 지정(1:N) → 칠러 상세 "공급 중인 CDU" 반영
  - 랙 상세/탱크 상세에 **CDU→칠러** 표기
  - 비활성/비칠러를 공급 칠러로 지정 시 **거부**
  - 칠러 **삭제 시** 공급 중 CDU 경고

## 8. Known limitation / 알려진 이슈

- **BUG-26 — 사용등록 경로 U 겹침 미검사**: 사용등록에서 랙 U 구간 겹침을 막지 않습니다(자산 등록/수정은 검사). *(추후 보완)*
- **BUG-28 — 관리번호 UNIQUE 제약 부재**: 서로 다른 장비에 같은 관리번호가 저장될 수 있습니다(스키마 변경 동반이라 보류). *(추후 UNIQUE 검토)*
- **BUG-29 — 일부 반납 경로에서 rack_id 미해제**: 과거 반납분 중 랙 배치가 남아 집계에 잔재로 보일 수 있습니다(확인 6건). **조사 예정, 본 릴리스 미포함.**
- **SEC — 사용등록 프리필 시 비밀번호 평문 표시**: 관리번호 프리필 시 접속정보 비밀번호가 화면/폼 값에 평문 노출될 수 있습니다. *(별도 보안 수리 대상)*
- (2.3.0 승계) 웹 백업 생성은 compose 배포에서 비동작 — 호스트 `bash scripts/backup.sh`(CLI) 사용.
